# Errors and diagnostics

## Exceptions

Database errors reach you as they come from the driver (`SqlException`). The library adds its own
`DatabaseException` (`cl2j.Database.Exceptions`) for misuse:

| Situation | Exception |
|---|---|
| The provider was never registered | `DatabaseException: No CommandBuilder registered for connection 'SqlConnection'` |
| A type with no column mapping | `No column type for 'X'. Declare one with [Column(TypeName = "...")].` |
| `QueryKey`, `QueryKeys` or `DeleteKey` on a type without exactly one key column | `X : Must have exactly one key, found N` |
| `NewKey<T>()` on a type with no `SelfGeneratedKey` | `No autogenerated key defined for 'X'` |
| An entity that is not `public` | `DatabaseException: Type X must be public` |
| A connection that is not a `SqlConnection` given to the SQL Server provider | `SqlConnection required. 'Y' received.` |
| `UpdateColumn` with a column the entity does not have, or a key column | `ArgumentException: Column 'x' not found or is a key column.` |

Other things that surface from the database or the reader:

| Situation | What you see |
|---|---|
| Missing schema | `SqlException: The specified schema name "x" either does not exist...` |
| `DropTable` on a missing table | `SqlException` (use `DropTableIfExists`) |
| A `SELECT` that lacks a column the class needs | `IndexOutOfRangeException` whose message is the column name |
| A `NULL` in a `Required` column | `SqlNullValueException` |
| Column type different from the property type | `InvalidCastException`; see [Type mapping](type-mapping.md) |
| A get-only property that is not `[Ignore]`d | On the first read of the type, a `DatabaseException`: `X.Y has no public setter, so a read cannot fill it. Mark it [Ignore] ... or give it a setter.` (before 6.6.0: a Roslyn `CS0200`) |
| A value the type cannot hold (`TimeSpan` over a day, `NaN`, a `decimal` over the declared precision) | An exception from the server or the driver; the value is not truncated silently (except the cases listed in [Type mapping](type-mapping.md), such as extra decimals, which are rounded) |

## Logging

There are two loggers, and they are configured in different places.

| What | Where it is logged | Configured by |
|---|---|---|
| **`IDatabase` calls**: an exception is logged and rethrown; `Query(sql)` logs the number of rows | the `ILogger` you passed to `SqlServerDatabase` | `DatabaseOptions.ExceptionLevel` (default `Debug`), `TraceLevel` (default `Trace`) of the instance you passed to `SqlServerDatabase` |
| **`DbConnection` extensions**: the text of every DDL, `Insert`, `Update` and `Delete` statement | the **static** `ConnectionExtensions.Logger` | `host.UseDatabase()`, or set it yourself |

- The exception entry of `Query`, `QuerySingle`, `Exists` and `Execute` includes the SQL and
  `parameters={param}`, so **parameter values can reach the logs** (the entry for `Insert`/`Update`/`DeleteKey`
  names only the type). Treat that log level accordingly, or filter the category.
- Exceptions are logged at `ExceptionLevel`, which defaults to `Debug`: with a typical `Information` minimum
  nothing is written. Set `ExceptionLevel = LogLevel.Error` to see failures. The exception is always rethrown.
- Only `Query<T>(sql, param)` traces the row count and duration, at `TraceLevel` (default `Trace`).
- `UseDatabase` takes its logger from `ILoggerFactory.CreateLogger("cl2j.Database")`, so the logging of a standard
  host works with nothing extra. The category is `cl2j.Database`; filter it in `Logging:LogLevel`. Without an
  `ILoggerFactory` it falls back to a registered non-generic `ILogger`; if there is none either, the static logger
  stays `null` and statement tracing is off. You can also assign `ConnectionExtensions.Logger` yourself.
- Static state is shared by the whole process, so two databases in one process share the logger and the
  `BulkInsertTimeout`.
- When a read fails, the generated mapper source is written to `Debug.WriteLine`, which helps when the cause
  is a property the compiler rejects.

```cs
ConnectionExtensions.Logger = loggerFactory.CreateLogger("cl2j.Database");
ConnectionExtensions.DatabaseOptions = new DatabaseOptions { TraceLevel = LogLevel.Debug };
```

## Seeing the SQL

`BuildSelectStatement<T>()` shows the `SELECT` for a type. The DDL, insert, update and delete text goes to
the trace log above. Tests that assert statement text without a server live in `StatementGenerationTests`,
`QueryByKeyStatementTests` and `SqlServerFormatterTests`.
