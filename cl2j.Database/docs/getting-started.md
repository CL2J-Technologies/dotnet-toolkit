# Getting started

From an empty project to a working table, in four steps.

## 1. Install

```powershell
dotnet add package cl2j.Database
dotnet add package cl2j.Database.SqlServer
```

`cl2j.Database` is the abstraction (attributes, `IDatabase`, the `DbConnection` extension methods).
`cl2j.Database.SqlServer` is the provider, built on `Microsoft.Data.SqlClient`. Target framework:
`net10.0`.

## 2. Describe a table

A table is a plain class. Every public property with a getter is a column unless it carries
`[Ignore]`. See [Entities and attributes](entities-and-attributes.md).

```cs
using cl2j.Database.DataAnnotations;

[Table("Customer")]
public class Customer
{
    [Column(Name = "Id", Key = KeyType.AutoGeneratedKey, Length = 36, KeyPrefix = "cus_")]
    public string Id { get; set; } = null!;

    [Column(Name = "Name", Length = 100, Required = true)]
    public string Name { get; set; } = null!;

    [Column(Name = "Email", Length = 200)]
    public string? Email { get; set; }

    [Column(Name = "CreatedAt")]
    public DateTimeOffset CreatedAt { get; set; }
}
```

## 3. Wire it up

There are four steps, and the last one is **outside dependency injection**:

```cs
using cl2j.Database;
using cl2j.Database.Databases;
using Microsoft.Extensions.DependencyInjection;
using Microsoft.Extensions.Hosting;
using Microsoft.Extensions.Logging;

var builder = Host.CreateApplicationBuilder(args);

// 1. Options (DatabaseOptions).
builder.Services.AddDatabase();

// 2. The provider.
builder.Services.AddSingleton<IDatabase>(sp => new cl2j.Database.SqlServer.SqlServerDatabase(
    connectionString,
    new DatabaseOptions(),
    sp.GetRequiredService<ILogger<cl2j.Database.SqlServer.SqlServerDatabase>>()));

var host = builder.Build();

// 3. Logger and options, once the host is built.
host.UseDatabase();

// 4. The SQL Server command builder (static, process-wide registry).
cl2j.Database.SqlServer.SqlServer.Register();

host.Run();
```

**Without step 4, everything compiles, the application starts, and only the first database call
fails:**

```
cl2j.Database.Exceptions.DatabaseException: No CommandBuilder registered for connection 'SqlConnection'
```

Why each step exists:

| Step | What it does |
|---|---|
| `AddDatabase()` | Registers `DatabaseOptions` with the options system. Its optional `register` callback only receives the `IServiceCollection`; it does not register the provider. |
| `SqlServerDatabase` | The `IDatabase` implementation. It opens a connection per call. |
| `UseDatabase()` | Publishes the logger and the options to **static** state (`ConnectionExtensions.Logger`, `ConnectionExtensions.DatabaseOptions`). Call it once, at startup. |
| `SqlServer.Register()` | Registers the SQL Server command builder in `CommandBuilderFactory`, a static registry. Calling it again replaces the previous registration, which is how you change the [identifier generator](keys.md#identifier-generators). |

`UseDatabase` takes its logger from `ILoggerFactory.CreateLogger("cl2j.Database")`, so the logging of a standard
host works with nothing extra. Without an `ILoggerFactory` it falls back to a registered non-generic `ILogger`;
if there is none either, statement tracing by the connection extensions is off. See
[Errors and diagnostics](errors-and-diagnostics.md#logging).

### Without a host

Nothing requires dependency injection. Register the provider and create the database yourself:

```cs
using cl2j.Database;
using cl2j.Database.Databases;
using Microsoft.Extensions.Logging.Abstractions;

cl2j.Database.SqlServer.SqlServer.Register();

// Optional: what the DbConnection extensions read (BulkInsertTimeout, trace level, logger).
ConnectionExtensions.DatabaseOptions = new DatabaseOptions { BulkInsertTimeout = TimeSpan.FromMinutes(5) };

IDatabase database = new cl2j.Database.SqlServer.SqlServerDatabase(
    connectionString, new DatabaseOptions(), NullLogger.Instance);
```

## 4. Use it

```cs
await using (var connection = await database.CreateConnection())
{
    await connection.CreateTableIfRequired<Customer>();
}

var customer = await database.Insert(new Customer
{
    Name = "Ada",
    Email = "ada@example.com",
    CreatedAt = DateTimeOffset.UtcNow
});
// customer.Id is now "cus_" + 32 hex characters.

var again = await database.QueryKeys<Customer>([customer.Id]);
var byName = await database.Query<Customer>(new { Name = "Ada" });
var one = await database.QuerySingle<Customer>(new { Id = customer.Id });

customer.Email = null;
await database.Update(customer);

await database.DeleteKey<Customer>(customer.Id);
```

## Things to know before you build on it

- **The first read of each type compiles code.** The row-to-object mapper is generated as C# and
  compiled with Roslyn (through `cl2j.Scripting`) the first time a type is read.
  `Microsoft.CodeAnalysis.CSharp` therefore has to be deployed with your application, and the first
  read of each type pays a one-off compile cost. Steady state is measured in
  [`benchmarks/README.md`](../../benchmarks/README.md). See
  [#42](https://github.com/CL2J-Technologies/dotnet-toolkit/issues/42).
- **Entity types must be `public`**, with a public parameterless constructor and public setters.
- **`IDatabase` is the simple surface.** Transactions, bulk insert and schema operations are on the
  `DbConnection` extension methods, which live in the `cl2j.Database` namespace (`using cl2j.Database;`).
  See [Transactions](transactions.md), [Bulk insert](bulk-insert.md) and [Schema](schema.md).
