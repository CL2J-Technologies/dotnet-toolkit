# Keys

`ColumnAttribute.Key` is a `KeyType`. What it does depends on the key type of the property.

| `KeyType` | Property type | In the DDL | On `Insert` / `BulkInsert` |
|---|---|---|---|
| `Key` | `int`, `long` | `IDENTITY(1,1) PRIMARY KEY` | Left out; the server numbers the row. |
| `Key` | `Guid` | `DEFAULT NEWID() PRIMARY KEY` | Left out; a value you set on the property is **ignored**. |
| `Key` | `string` | `varchar(n) NOT NULL` + `CONSTRAINT [PK_Table] PRIMARY KEY CLUSTERED` | Sent as you set it. Nothing generates it. |
| `AutoGeneratedKey` | `string` | As a string `Key` | Generated by the [identifier generator](#identifier-generators) and written back to the property. |
| `SelfGeneratedKey` | `string` | As a string `Key` | Sent as you set it. `NewKey<T>()` gives you a value. |
| `None` | any | not a key | |

If no column declares a key, a property named `Id` is treated as `KeyType.Key`.

Proven by `TypeKeyAndForeignTableTests`, `GeneratedKeyTests`, `StringKeyInsertTests`, `KeyAndJsonFixTests`
and `KeyDeclarationTests`.

## Generated string keys

```cs
[Column(Name = "Id", Key = KeyType.AutoGeneratedKey, Length = 36, KeyPrefix = "ord_")]
public string Id { get; set; } = null!;

var order = await database.Insert(new Order { Total = 10m });
// order.Id == "ord_" + 32 hex characters, e.g. "ord_c0f79aeb73af4b1b8dad84842df7f5ff"
```

- The default generator produces `KeyPrefix + Guid.ToString("N")`: the prefix length **plus 32
  characters**. That total has to fit `Length` (`"ord_"` + 32 = 36).
- A prefix makes an identifier in a log attributable to its table.
- **`AutoGeneratedKey` is always overwritten.** A value you set before `Insert` or `BulkInsert` is
  replaced. Use `SelfGeneratedKey` when you need to choose the key yourself.
- `NewKey<T>()` returns a fresh value for the **`SelfGeneratedKey`** column. It does not look at
  `AutoGeneratedKey` columns and throws for them
  ([#69](https://github.com/CL2J-Technologies/dotnet-toolkit/issues/69)).

```cs
[Column(Name = "Id", Key = KeyType.SelfGeneratedKey, Length = 36, KeyPrefix = "inv_")]
public string Id { get; set; } = null!;

var invoice = new Invoice { Id = await database.NewKey<Invoice>() };   // known before the insert
```

## Identifier generators

`IIdentifierGenerator` decides how generated keys are produced. The default is
`GuidIdentifierGenerator`. Pass your own to `SqlServer.Register`:

```cs
using cl2j.Database.CommandBuilders;
using cl2j.Database.Descriptors;

public class PrefixedV7Generator : IIdentifierGenerator
{
    public string GenerateKey(ColumnDescriptor columnDescriptor)
        => (columnDescriptor.ColumnAtribute.KeyPrefix ?? "") + Guid.CreateVersion7().ToString("N");
}

cl2j.Database.SqlServer.SqlServer.Register(new PrefixedV7Generator());
```

Keep the generated length within the column `Length`. Registering again replaces the previous SQL Server
registration (see [#29](https://github.com/CL2J-Technologies/dotnet-toolkit/issues/29)).

## Getting an identity back

`IDatabase.Insert` returns the entity and does **not** fill in an `IDENTITY` value. On a connection, ask for
it:

```cs
await using var connection = await database.CreateConnection();
int id = await connection.Insert<Counter, int>(new Counter { Label = "a" });   // long works the same
```

`Insert<TIn, TOut>` returns the value of the identity column.

## Reading and deleting by key

```cs
var one = await connection.QueryKey<Customer>("cus_...");                 // null when it is not there
var some = await connection.QueryKeys<Customer>(ids.Cast<object>());      // IN (...) list
await connection.DeleteKey<Customer>("cus_...");
await connection.Delete(customer);                                        // by the key value(s) of the instance
```

- `QueryKey`, `QueryKeys` and `DeleteKey` need **exactly one** key column; otherwise they throw a
  `DatabaseException` (`Must have exactly one key, found N`).
- `QueryKeys` takes `IEnumerable<object>`; a `List<int>` needs `.Cast<object>()`. `IDatabase.QueryKeys<T>`
  takes `IEnumerable<string>`.
- `QueryKeys` sends the keys as parameters, in batches of 2000. An empty list runs no statement and
  returns an empty list.
- Key values are always parameters, never part of the SQL text.
- On a `varchar` key column, `QueryKey` binds the key as `varchar`, so the index stays usable. See
  [Parameters and the plan cache](parameters-and-plan-cache.md).

## Composite keys

Mark every column of the key with `Key = KeyType.Key`:

```cs
[Table("OrderLine")]
public class OrderLine
{
    [Column(Name = "OrderId", Key = KeyType.Key)] public int OrderId { get; set; }
    [Column(Name = "LineNo", Key = KeyType.Key)] public int LineNo { get; set; }
    [Column(Name = "Sku", Length = 20)] public string? Sku { get; set; }
}
```

- `CreateTable` emits **one** table-level `CONSTRAINT [PK_OrderLine] PRIMARY KEY ([OrderId], [LineNo])`, and
  every key column is `NOT NULL`. Before 6.6.0 it emitted a `PRIMARY KEY` per column and the server refused it.
- **You supply every key column.** None of them is an identity, a `NEWID()` default or otherwise generated by
  the server, whatever its type: `Insert` and `BulkInsert` send them all, so an `int` or `Guid` you leave at its
  default is written as that default.
- `Update` and `Delete(entity)` filter on every key column with `AND`; `UpdateColumn` works on a row of such a
  table. A duplicate key is refused by the server.
- `QueryKey`, `QueryKeys` and `DeleteKey` take one key value, so they throw for a composite key. Query by
  example instead: `Query<T>(new { OrderId = 1, LineNo = 2 })`.
- A table with a single key column is unchanged.

Proven by `DefectFixTests` (every provider) and the DDL text tests (`KeyDeclarationTests`,
`PostgreSqlStatementTests`, `MySqlCompositeKeyStatementTests`).

## Limits

- **A composite key is supported since 6.6.0**; see [Composite keys](#composite-keys). `QueryKey`, `QueryKeys`
  and `DeleteKey` still need exactly one key column.
- **An entity with no key** can be created and inserted into, but `Update` and `Delete` produce invalid SQL
  (`Incorrect syntax near 'WHERE'`) and `QueryKey` throws.
- **Give a string key a `Length`.** Without one the column is `varchar(max)`, which SQL Server refuses as a
  key (`is of a type that is invalid for use as a key column in an index`).
