# Implementing a cl2j.Database provider

A provider teaches `cl2j.Database` one database engine: how to quote names, which column type
each CLR type gets, how the server hands back a generated key, and how to bulk-load rows. Since
6.6.0 everything else — the statements, the parameter binding, the generated reader — is shared,
and a provider is a short subclass of `RelationalCommandBuilder` plus a test fixture.

`cl2j.Database.SqlServer` is the reference implementation. The values quoted below for MySQL and
PostgreSQL come from the two spikes that preceded the providers; check them against the server.

## 1. What the core already does

| Concern | Where | Provider involvement |
|---|---|---|
| Every statement (create, drop, exists, insert, update, update column, delete, query, query by key, query by keys) | `RelationalCommandBuilder`, `CommandBuilderHelpers` | none, unless the engine needs different SQL (every statement is `virtual`) |
| Which columns an INSERT and a bulk insert leave out | `CommandBuilderHelpers.IsSuppliedByTheServer` (int/long/Guid `KeyType.Key`) | the key DDL must make the server fill those in |
| Which key is an identity | `CommandBuilderHelpers.IsIdentity` (int/long `KeyType.Key`) | supply the retrieval suffix |
| Parameter types and declarations | `ParameterDeclaration`, `ParameterTyping` | adjust per parameter in `PrepareParameter` |
| Enum parameters | bound as `Int32` (value and null) | none |
| `DateTime` parameters | bound as `DbType.DateTime2` unless the column declares another type | adjust in `PrepareParameter` if the driver needs it |
| Identity returned by `Insert<TIn,TOut>` | converted to `TOut` (`Convert.ChangeType`, invariant, overflow throws) | none: return the server's own type |
| Splitting `QueryKeys` into several statements | `QueryKeyBatches`, by `MaxKeysPerStatement` | override the batch size if the engine allows more parameters |
| Reading rows | the generated reader, cached **per entity type, not per provider** | none (see section 4) |
| Bulk insert preamble (descriptor, columns, `DataTable` with JSON serialised and null `DateTimeOffset` stamped) | `RelationalCommandBuilder.BulkInsert` | write the `DataTable` to the server |

## 2. Checklist: the provider project `cl2j.Database.<Name>`

### 2.1 The command builder

`internal sealed class <Name>CommandBuilder(IIdentifierGenerator? identifierGenerator) : RelationalCommandBuilder(identifierGenerator)`

Must implement:

- [ ] **`bool Support(DbConnection connection)`** — true for the driver's connection type only
  (`connection is NpgsqlConnection`). The registry returns the first builder that supports a
  connection.
- [ ] **`string QuoteIdentifier(string name)`** — used for every table, schema and column name.
  SQL Server `[name]`; MySQL `` `name` `` with a backtick doubled; PostgreSQL `"name"` with a
  double quote doubled (quoting also stops PostgreSQL folding the name to lower case).
- [ ] **`DefaultSchemaName` or `CurrentSchemaExpression`** — the schema of a table whose type names
  none, for `TableExists`. A name is bound as a parameter (SQL Server `"dbo"`); an expression is
  written into the SQL (MySQL `DATABASE()`, PostgreSQL `current_schema()`). Overriding neither
  throws `NotSupportedException` on the first `TableExists`.
- [ ] **`string? MapClrType(Type type, ColumnDescriptor column)`** — the column type for the
  *unwrapped* CLR type (`int?` arrives as `int`). Return `null` for a type you do not map: the base
  throws the "declare one with `[Column(TypeName = ...)]`" error. `TypeName`, `Json` and the
  ` DEFAULT ...` suffix are handled by the base. Use `FormatDecimal(attribute, "numeric")` for
  decimals: it refuses a decimal without a declared precision. Types to cover: enum, bool, byte,
  short, int, long, float, double, decimal, Guid, string, byte[], DateTime, DateTimeOffset,
  DateOnly, TimeOnly, TimeSpan, char.
- [ ] **`string GetJsonColumnType(ColumnAttribute attribute)`** — SQL Server `varchar(max|n)`;
  PostgreSQL `jsonb` without a length, `varchar(n)` with one.
- [ ] **`string IdentityKeyDeclaration`** — appended to an int/long key column. SQL Server
  ` IDENTITY(1,1) PRIMARY KEY`; MySQL ` AUTO_INCREMENT PRIMARY KEY`; PostgreSQL
  ` GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` (`BY DEFAULT`, so a caller can still seed a row).
- [ ] **`string GuidKeyDeclaration`** — appended to a Guid key column; the server must generate the
  value. SQL Server ` DEFAULT NEWID() PRIMARY KEY`; MySQL ` DEFAULT (UUID()) PRIMARY KEY`
  (8.0.13+); PostgreSQL ` DEFAULT gen_random_uuid() PRIMARY KEY` (13+).
- [ ] **`string GetIdentityRetrieval(TableDescriptor table, ColumnDescriptor identity)`** — a suffix
  appended to the INSERT so that `ExecuteScalar` returns the generated key as **one scalar**. SQL
  Server `;SELECT CAST(SCOPE_IDENTITY() AS int|bigint)`; MySQL `;SELECT LAST_INSERT_ID()` (a `ulong`
  is fine, the core converts); PostgreSQL ` RETURNING {identity.NameFormatted}`.
- [ ] **`Task WriteBulkAsync(DbConnection connection, TableDescriptor table, IReadOnlyList<ColumnDescriptor> columns, DataTable rows, CancellationToken cancellationToken, DbTransaction? transaction)`**
  — write `rows` to `table`. `columns` already leaves out server-supplied keys and matches the
  `DataTable` columns one to one, in order. Map columns by name, not by ordinal. Take the timeout
  from `ConnectionExtensions.DatabaseOptions.GetBulkInsertTimeoutSeconds(connection.ConnectionTimeout)`.
  Decide and document what happens on an empty input and on a duplicate key (all-or-nothing like
  `SqlBulkCopy` and PostgreSQL's `COPY`, or partial like MySQL's `LOAD DATA LOCAL`).

May override:

- [ ] **`int MaxKeysPerStatement`** (default 2000, under SQL Server's 2,100-parameter limit). One
  parameter per key; PostgreSQL accepts up to 65,535 parameters per statement.
- [ ] **`void PrepareParameter(DbParameter parameter, ColumnDescriptor? column)`** — see 2.2.
- [ ] Any statement method, when the engine needs different SQL. Keep the parameter names the base
  uses: the core binds by name.

### 2.2 The parameter seam: `PrepareParameter`

Called by `ConnectionExtensions` for **every** parameter it binds — Insert, Update, UpdateColumn,
Delete, DeleteKey, QueryKey, QueryKeys, Query, QuerySingle, Execute, TableExists — after the core
has set the value, `DbType`, size and precision, and before the command runs. `column` is the
column the value belongs to, or `null` when there is none (a `TableExists` name). It is **not**
called on the bulk path, which writes values itself.

Contract: adjust the parameter in place; never change the meaning of the value, never add or
remove parameters, never rewrite SQL text. Known needs:

- PostgreSQL: a `DateTimeOffset` value → `ToUniversalTime()` (Npgsql refuses another offset); a
  JSON column (`Json`, no `TypeName`, no `Length`) → `NpgsqlDbType.Jsonb` on the `NpgsqlParameter`;
  a `DateTime` arrives as `DbType.DateTime2`, i.e. `timestamp`, which refuses `Kind=Utc` — give it
  `DateTimeKind.Unspecified`.
- MySQL: none known.

### 2.3 Registration and the `IDatabase` class

```csharp
public static class <Name>
{
    public static void Register(IIdentifierGenerator? identifierGenerator = null)
        => CommandBuilderFactory.Register(new <Name>CommandBuilder(identifierGenerator));
}

public class <Name>Database(string connectionString, DatabaseOptions options, ILogger logger)
    : BaseDatabase(options, logger)
{
    public override async Task<DbConnection> CreateConnection()
    {
        var connection = new <Driver>Connection(connectionString);
        await connection.OpenAsync();
        return connection;
    }
}
```

These two stay per provider on purpose: a shared base would save a few lines and add a public type.

### 2.4 Project

- [ ] Copy `cl2j.Database.SqlServer.csproj`: `IsPackable=true`, a NuGet `Description`, a reference
  to the driver and to `cl2j.Database`. No version: the repository publishes one shared version.
- [ ] Add it to `dotnet-toolkit.slnx`.
- [ ] A section in `cl2j.Database/README.md`: type mapping, bulk-insert strategy, and every
  behaviour that differs from SQL Server (offset kept or dropped, fractional digits, collation,
  size limits).

## 3. Checklist: the integration tests `cl2j.Database.<Name>.IntegrationTests`

The provider-neutral tests live in `cl2j.Database.IntegrationTests.Shared` as abstract
`XxxTestsBase` classes. A provider runs them by supplying a fixture and one thin class per base.

- [ ] Reference `cl2j.Database.IntegrationTests.Shared`, the provider, xUnit and the Testcontainers
  module for the engine (pin the image: `mysql:8.4`, `postgres:17`).
- [ ] A fixture implementing **`IDatabaseFixture`**, shared through an xUnit collection:
  - `string ConnectionString`;
  - `Task<DbConnection> OpenAsync()` — a new, open connection per call;
  - `IDatabase CreateDatabase(DatabaseOptions options, ILogger logger)` — the provider's `IDatabase`;
  - `Type ConnectionType` — compared exactly (`SqlConnection`);
  - `Type ServerExceptionType` — the exact type the driver throws for a rejected statement
    (`SqlException`, `MySqlException`, `PostgresException`);
  - `string CatalogScopeFilter` — appended to `INFORMATION_SCHEMA.COLUMNS` queries: SQL Server
    `""`, MySQL `" AND TABLE_SCHEMA = DATABASE()"`, PostgreSQL `" AND TABLE_SCHEMA = current_schema()"`;
  - register the provider in `InitializeAsync`, before the first test.
- [ ] One `[Collection(...)] public class XxxTests(<Name>Fixture fixture) : XxxTestsBase(fixture)`
  for each base: `BulkAndBatch`, `ConnectionGap`, `DatabaseFacade`, `Existence`, `GeneratedKey`,
  `KeyAndJsonFix`, `KnownDefect`, `NullableColumn`, `Reader`, `RoundTrip`, `StringKeyInsert`,
  `Transaction`, `TypeEdgeValue`, `TypeKeyAndForeignTable`, `TypeMatrix`, `WideValue`.
- [ ] Override the hooks whose default — always SQL Server's value — does not hold:

| Hook | SQL Server default | Notes for other engines |
|---|---|---|
| `ReaderTestsBase.MomentValue` | `2026-09-06 14:30:15 -04:00` | equality compares instants; MySQL drops the offset, so use UTC there |
| `NullableColumnTestsBase.IntTypeName` / `DateTimeTypeName` / `GuidTypeName` | `int` / `datetime2` / `uniqueidentifier` | catalog `DATA_TYPE` of `int?`, `DateTime?`, `Guid?` |
| `WideValueTestsBase.LongTypeName` / `DoubleTypeName` / `GuidTypeName` | `bigint` / `float` / `uniqueidentifier` | catalog `DATA_TYPE` of `long`, `double`, `Guid` |
| `BulkAndBatchTestsBase.BulkRowCount` | 500 | rows in the bulk test |
| `BulkAndBatchTestsBase.KeyBatchRowCount` | 2500 | must exceed `MaxKeysPerStatement`, so the split is exercised |
| `TypeTestsBase.TemporalFractionalDigits` | 7 | 6 on MySQL and PostgreSQL |
| `TypeTestsBase.ValueToWrite(object)` | identity | MySQL `datetime` starts at year 1000: move the minimum dates |
| `TypeTestsBase.ExpectedValue(object)` | identity | a `DateTimeOffset` comes back as `ToUniversalTime()` on MySQL and PostgreSQL |
| `TypeMatrixTestsBase.ExpectedColumnType(Type)` | SQL Server catalog names | the catalog `DATA_TYPE` per mapped type (below) |
| `TypeEdgeValueTestsBase.StoresNonFiniteDoubles` | false | PostgreSQL stores NaN and ±Infinity (unverified) |
| `TypeEdgeValueTestsBase.RefusesTimeSpanOutsideADay` | true | false for MySQL `time` and PostgreSQL `interval` |

  The `TypeTestsBase` hooks are inherited by both the matrix and the edge-value bases: override them
  in both derived classes, forwarding to one static helper.

  Expected `ExpectedColumnType` values (from the spikes):
  - PostgreSQL: boolean; smallint (byte, short); integer (int, enum); bigint; real;
    double precision; numeric; uuid; text; bytea; timestamp without time zone;
    timestamp with time zone; date; time without time zone (TimeOnly); interval (TimeSpan);
    character.
  - MySQL: tinyint (bool, byte); smallint; int; bigint; double (float and double); decimal; char (Guid, char);
    varchar (a string with a length); longblob; datetime (DateTime, DateTimeOffset); date; time (TimeOnly, TimeSpan).

- [ ] Raw SQL in a test is written with `[Name]` and passed through `TestSql.Quote(connection, sql)`,
  which applies the provider's quoting.
- [ ] Provider-only behaviour — offsets, collation, precision, value too long, duplicate keys in a
  bulk load, a second connection configuration (run a base twice through a fixture adapter) — goes
  in provider-specific test classes, not in the shared bases.
- [ ] Not yet proven off SQL Server; expect to adjust: denormal `float`/`double` values, all three
  `DateTimeKind`s on `DateTime`, `decimal(38,28)`, and the supplied-Guid-key test.

## 4. The generated reader

The reader is compiled once per entity type and cached by type only, so the code it emits must
work for every driver. It already accepts what the known drivers hand back for a property type:

| Property | Accepted from the driver |
|---|---|
| `byte` | `byte`, or any integer converted with overflow checking (Npgsql: `short`) |
| `char` | `char` or a one-character `string` |
| `DateOnly` | `DateOnly` or `DateTime` |
| `TimeOnly` | `TimeOnly` or `TimeSpan` |
| `DateTimeOffset` | `DateTimeOffset`, or `DateTime` read as UTC (`Local` converted first) |
| enum | the integer |
| `float` | `float`, or any other number converted (MySQL keeps a float in a `double` column) |

If a new driver hands back yet another shape, extend `DbReaderExtensions.ConversionOf`, keeping the
emitted code provider-neutral; never branch on the provider there.

## 5. Running the tests

Integration tests start the server in Docker through Testcontainers and fail rather than skip when
Docker is missing. On Windows machines with Smart App Control, freshly built test assemblies are
blocked (0x800711C7): run the tests in WSL from a clone outside `/mnt/c`.
