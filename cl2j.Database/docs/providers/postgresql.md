# PostgreSQL provider

`cl2j.Database.PostgreSql` runs the `cl2j.Database` API on PostgreSQL through [Npgsql](https://www.npgsql.org/)
10. It is a thin layer on the shared `RelationalCommandBuilder` (see
[implementing-a-provider.md](implementing-a-provider.md)): the statements are the base's, and the provider
supplies the quoting, the type map, the identity retrieval, three parameter adjustments and the bulk load.

**Requires PostgreSQL 13 or later.** A `Guid` key is declared `DEFAULT gen_random_uuid()`, which is built in
from 13 (earlier versions need the `pgcrypto` extension).

## Setup

The same four steps as the SQL Server setup in the [README](../../README.md), with the PostgreSQL types:

```csharp
builder.Services.AddDatabase();

builder.Services.AddSingleton<IDatabase>(sp => new cl2j.Database.PostgreSql.PostgreSqlDatabase(
    connectionString,   // "Host=...;Database=...;Username=...;Password=..."
    new DatabaseOptions(),
    sp.GetRequiredService<ILogger<cl2j.Database.PostgreSql.PostgreSqlDatabase>>()));

var host = builder.Build();
host.UseDatabase();

// The command builder lives in a static, process-wide registry.
cl2j.Database.PostgreSql.PostgreSql.Register();
```

Or use the `DbConnection` extensions directly on an `NpgsqlConnection`, after `Register()`. `Register` takes
the same optional `IIdentifierGenerator` as the SQL Server provider, and registering again replaces the
previous registration.

## Type mapping

| CLR type | Column | Notes |
| --- | --- | --- |
| `int`, enums | `integer` | |
| `long` | `bigint` | |
| `short`, `byte` | `smallint` | There is no one-byte integer in PostgreSQL. A `byte` is written as `smallint` and read back as a `byte`. |
| `bool` | `boolean` | |
| `float` / `double` | `real` / `double precision` | `NaN` and the infinities are stored. |
| `decimal` | `numeric(p,s)` | `Length` and `Decimals` are required, as on SQL Server. |
| `string` | `varchar(n)` or `text` | `text` when no `Length` is declared. |
| `char` | `char(1)` | |
| `Guid` | `uuid` | |
| `byte[]` | `bytea` | |
| `DateTime` | `timestamp` (without time zone) | The ticks are stored as written; the kind is dropped and the value reads back `Unspecified`. |
| `DateTimeOffset` | `timestamptz` | The instant is stored, not the offset. See below. |
| `DateOnly` | `date` | |
| `TimeOnly` | `time` | |
| `TimeSpan` | `interval` | Not limited to a day (SQL Server's `time` is). |
| JSON column (`Json = true`) | `jsonb` | `varchar(n)` when a `Length` is declared. `TypeName = "json"` is honoured. |

`TypeName` overrides the mapping for the column, as on the other providers.

Keys: an `int` or `long` `KeyType.Key` is `GENERATED BY DEFAULT AS IDENTITY`; a `Guid` key is
`DEFAULT gen_random_uuid()`; a string key is `NOT NULL` with a primary key constraint. The identity is
`BY DEFAULT` rather than `ALWAYS`, so a row can be seeded with a key of its own through raw SQL.

## Behaviour that differs from SQL Server

- **`DateTimeOffset` loses its offset.** `timestamptz` holds an instant. The value is sent in UTC and comes
  back with a zero offset: the same moment, not the same offset. Equality of `DateTimeOffset` compares the
  instant, so comparisons keep working; code that displays `.Offset` does not.
- **Six digits of precision.** `timestamp`, `timestamptz` and `time` keep microseconds. SQL Server's
  `datetime2` and `time` keep 100 ns ticks, so the last digit of a tick is dropped on the way in.
- **Comparisons are case- and accent-sensitive.** A query by example for `"eclair"` does not find
  `"Éclair"`, where a default SQL Server collation would. Use a `TypeName` such as `citext` (an extension
  that must be installed) or raw SQL with `ILIKE` when that is wanted.
- **Unquoted identifiers fold to lower case in raw SQL.** Every identifier the library emits is double
  quoted, so the catalog holds `"Customer"`, not `customer`. Raw SQL written for SQL Server must quote the
  names the same way: `SELECT * FROM "Customer"` works, `SELECT * FROM Customer` fails with
  `42P01: relation "customer" does not exist`.
- **Raw SQL uses `@name` parameters**, as elsewhere. Npgsql rewrites them to its own positional form.
- **`Insert<TIn, TOut>` returns the column's own type.** The identity comes back through `RETURNING`, so an
  `integer` identity is an `int` and a `bigint` one is a `long`, with no cast.
- **A null JSON value** is written as the JSON `null` by `Insert` and as SQL `NULL` by `BulkInsert`. Both
  read back as `null`. This is the core's behaviour, not the provider's.
- **Names are used as written in a parameter.** A double quote in a column name is quoted correctly in the
  SQL but would also end up in the parameter name, which the core does not escape. Avoid it in column
  names; a table name is fine.
- **A table with no schema** is looked up in `current_schema()` (the first schema of the search path),
  which is what an unqualified name resolves to. Declare `Schema = "..."` to use another one; the schema
  itself must exist.

## Bulk insert

`BulkInsert` uses binary `COPY ... FROM STDIN`.

- **Atomic.** The batch is one `COPY`: a duplicate key, a value too long for its column or any other
  constraint violation fails the whole batch and none of it is written. Disposing the importer without
  completing it cancels the copy.
- **Transactions.** Pass the transaction to `BulkInsert(items, token, transaction)`. The rows are visible to
  the transaction at once, to other connections only after it commits, and gone if it rolls back. A
  transaction that belongs to another connection is refused with a `DatabaseException`.
- **Cancellation.** The token is honoured before the copy starts and between rows. A token that is already
  cancelled leaves the connection untouched and usable. A token cancelled in the middle of a large batch
  stops the copy and nothing is written; Npgsql may close the connection when it is cancelled in the middle
  of the protocol exchange, so do not reuse a connection after a cancellation you did not expect.
- **An empty batch** does nothing and does not reach the server.
- **Timeout.** The copy honours `DatabaseOptions.BulkInsertTimeout`, falling back to the connection timeout.
- **Types are strict.** COPY sends each value in the binary form of its column, and the server refuses a
  mismatch. The provider picks the wire type from the CLR type (and from `TypeName` when one is declared),
  and applies the same UTC and JSON adjustments as a normal insert. A `DateTime` is written as it is,
  whatever its kind.

## Testing

The integration suite starts a `postgres:17` container with Testcontainers, so Docker has to be running; it
fails rather than skips when it is not. Run it with:

```
dotnet test cl2j.Database/cl2j.Database.PostgreSql.IntegrationTests
```

The unit tests (`cl2j.Database.PostgreSql.Tests`) need neither Docker nor a server.
