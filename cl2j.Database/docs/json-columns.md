# JSON columns

`[Column(Json = true)]` stores a property as JSON text and reads it back.

```cs
public class Settings
{
    public string? Theme { get; set; }
    public List<string> Tags { get; set; } = [];
}

[Table("Profile")]
public class Profile
{
    [Column(Name = "Id", Key = KeyType.AutoGeneratedKey, Length = 36, KeyPrefix = "pro_")]
    public string Id { get; set; } = null!;

    [Column(Name = "Settings", Json = true)]
    public Settings? Settings { get; set; }
}
```

- **Column type:** `varchar(max)`, or `varchar(Length)` when you give a `Length`.
- **Insert and BulkInsert** serialize with `System.Text.Json`; reading uses the default
  `JsonSerializer.Deserialize` options. A class or a list of strings is the usual payload.
- **`null`:** `Insert` writes the text `null`, `BulkInsert` writes SQL `NULL`. Both read back as `null`
  (`KeyAndJsonFixTests`).

## Write options, and what they drop

The write side uses `ConnectionExtensions.JsonSerializeOptions`:
`DefaultIgnoreCondition = WhenWritingDefault` and `UnsafeRelaxedJsonEscaping` (non-ASCII characters are not
`\u`-escaped). Because of `WhenWritingDefault`, **properties holding the default of their type are not
written**: `0`, `false`, `null`, `Guid.Empty`.

That is harmless until a property's initializer is not its type default:

```cs
public class Retry { public int Count { get; set; } = 3; }

// Stored with Count = 0: the "0" is not written -> {}. Read back: Count == 3.
```

If a zero or `false` must survive, use the type default as the initial value, or a nullable type
(`int?`) that defaults to `null`. This is the configured behaviour, found while writing these docs; no test
covers it.

## Unicode: `varchar` loses non-Latin text

A JSON column is `varchar`, so characters outside the column collation (Windows-1252 by default) are
silently replaced by `?`:

```
["café", "Привет", "日本"]   ->   café / ?????? / ??
```

This is true for `Insert` and `BulkInsert`. Declare the column as Unicode:

```cs
[Column(Name = "Tags", Json = true, TypeName = "nvarchar(max)")]
public List<string> Tags { get; set; } = [];
```

With `TypeName = "nvarchar(max)"` the same payload round-trips (verified against SQL Server 2022; no test in the
repository covers it yet).

## Querying inside JSON

The library treats the column as opaque text. To filter on a value inside it, use SQL (`JSON_VALUE`,
`OPENJSON`) with `Query<T>(sql, param)`; query by example cannot compare a JSON property.
