# Edge cases

Behaviour that surprises people, in one place. Each entry says whether a repository test proves it or
whether it was observed against SQL Server 2022 while writing these docs (**observed**: no test yet).

## Reading

- **Columns are matched by name, not by position.** Extra columns are ignored; a missing one throws an error
  that names it. (`ReaderTests`, `DbReaderExtensionsTests`.)
- **The column type must be the property type.** `tinyint` into `int` throws `InvalidCastException`; narrower
  integers do not widen. `datetime`, `smalldatetime`, `datetime2`, `money` and `numeric` read fine.
  (`TypeKeyAndForeignTableTests`.) See [Type mapping](type-mapping.md#reading-tables-the-library-did-not-create).
- **A `NULL` in a `Required` column throws** (`SqlNullValueException`); in an optional `int` it reads as `0`.
  Use `int?` to keep the `NULL`. (**Observed.**)
- **Get-only properties must be `[Ignore]`d**, or the first read of the type fails to compile its mapper.
  (**Observed.**)
- **Nested public classes work; non-public ones are refused.** (`TypeKeyAndForeignTableTests`,
  `DbReaderExtensionsTests`.)

## Querying

- **`new { Name = (string?)null }` matches nothing**, because it becomes `[Name] = NULL`. A `null` example
  object returns every row. (**Observed**; the second half is tested.)
- **No `LIKE`, `OR`, range or `IN` by example.** Use SQL.
- **`QueryKeys` batches at 2000 keys**, and an empty list sends nothing. (`QueryKeyBatchesTests`,
  `BulkAndBatchTests`.)
- **The `varchar` index trick does not apply to anonymous-parameter paths** ([#43](https://github.com/CL2J-Technologies/dotnet-toolkit/issues/43)).
  See [Parameters and the plan cache](parameters-and-plan-cache.md).

## Writing

- **`AutoGeneratedKey` is overwritten**, even when you set it. A caller-supplied `Guid` for a `Key` column is
  ignored too. (`GeneratedKeyTests`, `TypeKeyAndForeignTableTests`; the string case is **observed**.)
- <a id="default-is-ddl-only"></a>**`Default` is DDL only.** The generated `INSERT` lists every non-generated
  column, so a `null` property is written as `NULL` and the column default is never used. A raw
  `INSERT` that omits the column gets the default. (**Observed**; the DDL text is tested.)
- **A `DateTimeOffset` is stamped with "now" only by `UpdateColumn(..., null)` on a non-nullable
  `DateTimeOffset` property.** A `DateTimeOffset?` set to `null` stays `NULL` on `Insert` and `BulkInsert`.
  (`UpdateColumn_with_no_value_for_a_timestamp_stamps_the_current_time`, `Insert_round_trips_null`,
  `BulkInsert_round_trips_null`.)
- **`Update` rewrites every non-key column**: a stale copy overwrites a newer row. There is no concurrency
  token.
- **`BulkInsert` with a lazy `IEnumerable` and an `AutoGeneratedKey` fails** (`InvalidOperationException: Column 'Id' does not allow DBNull.Value`).
  Pass a list. See [Bulk insert](bulk-insert.md#materialise-your-sequence). (**Observed**; defect.)
- **`BulkInsert` takes its timeout from the static options**, not from the instance given to the database.
  (`BulkInsertTimeoutTests` for the arithmetic.)

## Text and JSON

- **`string` and `char` are `varchar`**: characters outside the collation become `?` silently
  (`TypeEdgeValueTests`). JSON columns are `nvarchar(max)` since 6.6.0 and keep non-Latin text; a table
  created before then keeps `varchar` until you migrate the column. See [JSON columns](json-columns.md#unicode).
  (`DefectFixTests`.)
- **JSON writes every property**, including `0`/`false`/`null`, so a non-default initializer no longer wins on read
  (fixed in 6.6.0; rows written earlier are unchanged). See [JSON columns](json-columns.md#write-options).
- **A JSON `null`** is the text `null` on `Insert` and SQL `NULL` on `BulkInsert`; both read back as `null`.
  (`KeyAndJsonFixTests`.)

## Schema

- **`CreateTable` supports one key column**; a composite key fails on the server. (**Observed.**)
- **A string key needs a `Length`** (`varchar(max)` cannot be a key). (**Observed.**)
- **A missing database schema is not created.** (**Observed.**)
- **An entity with no key** can be created and inserted into, but `Update` and `Delete` fail and `QueryKey`
  throws. (**Observed.**)
- **Nothing migrates.** A changed class never alters its table.

## Process-wide state

- `SqlServer.Register()`, `ConnectionExtensions.Logger` and `ConnectionExtensions.DatabaseOptions` are static.
  Registering again replaces the earlier registration (`CommandBuilderFactoryConcurrencyTests`,
  `RegistrationTests`).
- Entity descriptions are cached per type and formatter (`DescriptorCacheTests`).
- `UseDatabase()` only sets the static logger when a non-generic `ILogger` is registered
  ([#68](https://github.com/CL2J-Technologies/dotnet-toolkit/issues/68)).
