# Insert, update and delete

```cs
var customer = await database.Insert(new Customer { Name = "Ada", CreatedAt = DateTimeOffset.UtcNow });

customer.Email = "ada@example.com";
await database.Update(customer);                       // every column, WHERE on the key column(s)
await database.Update(customer, "Name", "Ada L.");     // one column; the key goes in the WHERE

await database.DeleteKey<Customer>(customer.Id);       // by key value
```

On a connection there are also `Delete(entity)` (by the key value(s) of the instance), `UpdateColumn` and
`Insert<TIn, TOut>`:

```cs
await using var connection = await database.CreateConnection();
await connection.Delete(customer);
await connection.UpdateColumn(customer, "Email", (string?)null);
int id = await connection.Insert<Counter, int>(new Counter());     // identity value
```

## Insert

- `Insert` sends every column **except** server-generated keys (`int`/`long` identity, `Guid`
  `NEWID()`). It returns the same instance, with an `AutoGeneratedKey` filled in. See [Keys](keys.md).
- **A `[Column(Default = ...)]` is never used by the library's own `Insert`.** The statement lists every
  non-generated column, so a `null` is written as `NULL`; the `DEFAULT` only applies to rows inserted by other
  means. See [Edge cases](edge-cases.md#default-is-ddl-only).
- Values are parameters, never inlined; see [Parameters and the plan cache](parameters-and-plan-cache.md).
- `IDatabase.Insert` does not fill in an `IDENTITY` value; use `Insert<TIn, TOut>` on a connection.

## Update

- `Update(entity)` writes every non-key column and filters on the key column(s). Setting a property to
  `null` writes `NULL`: the whole entity is what you send, there is no change tracking and no
  concurrency token. Two writers updating the same row overwrite each other.
- `Update` on an entity with no key does not produce valid SQL (`Incorrect syntax near 'WHERE'`).
- `Update(entity, "Column", value)` / `UpdateColumn` writes a single column.
  - The column must exist on the entity and must not be a key column; otherwise `ArgumentException`.
  - Pass the column name with its declared case: the statement is built case-sensitively.
  - **A non-nullable `DateTimeOffset` column given `null` is stamped with the current UTC time.** A
    `DateTimeOffset?` given `null` is set to `NULL`. This is the one place the library writes "now" for you
    (`UpdateColumn_with_no_value_for_a_timestamp_stamps_the_current_time`).
- An update that matches no row is not an error, and the call returns nothing: check with
  `Execute` (it returns the affected count) when you need to know.

## Delete

- `DeleteKey<T>(key)` needs exactly one key column. `Delete(entity)` works with a composite key.
- Deleting a key that does not exist is not an error.
- To delete by something other than the key, use SQL: `Execute("DELETE FROM [T] WHERE ...", param)` returns
  the number of rows removed.

## Concurrency and consistency

There is no unit of work. Each `IDatabase` call is its own connection and its own statement. To make several
writes succeed or fail together, use a [transaction](transactions.md) on a connection.
